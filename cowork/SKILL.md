# Signal Brief

แปลงผลสแกนที่คำนวณมาแล้ว → สรุปที่ Nana อ่านแล้วตัดสินใจได้ทันที
**ห้ามคำนวณ indicator เอง** ตัวเลขทุกตัวมาจาก `signals.json` เท่านั้น

## ที่มาของไฟล์

repo เป็น public — อ่านตรงได้ผ่าน raw.githubusercontent.com (ไม่ต้อง auth):

```
https://raw.githubusercontent.com/Naxyz23/agent-trade/main/data/signals.json
```

ใช้ WebFetch หรือ `curl` ดึงไฟล์นี้ก่อนเสมอ ก่อนตอบอะไรเกี่ยวกับสัญญาณ
ถ้าดึงไม่ได้ (404 / connection error) → repo ยังไม่ได้ push หรือ path ผิด บอก Nana ตรง ๆ
อย่าเดาว่ามีสัญญาณอะไร

## ขั้นตอน

1. ดึงไฟล์ล่าสุด ตรวจ `generated_at` — เก่ากว่า 30 ชั่วโมงให้บอกว่าข้อมูลค้าง
   (GitHub Action อาจล่ม หรือยังไม่เคยรันเลย)

2. **ช่วงทดสอบ (สัปดาห์แรก): ส่งสรุปทุกรอบไม่ว่าจะมีสัญญาณหรือไม่**
   เพื่อให้ Nana เห็นว่าระบบทำงานจริง ไม่ใช่แค่เงียบไปเฉย ๆ
   ถ้า `signals` ว่าง ให้บอกสั้น ๆ ว่า "สแกนแล้ว ไม่มีอะไรเข้าเงื่อนไข" พร้อมเวลาที่สแกน
   และภาพรวม 3-4 บรรทัดจาก `snapshot` (ราคาล่าสุด, RSI, regime ของ 2-3 ตัวที่น่าสนใจ)
   — ไม่ต้องยืดยาว แค่ให้เห็นว่าเครื่องยนต์ยังทำงานอยู่

3. เรียงลำดับการเล่าเมื่อมีสัญญาณ: **halts → exit → entry → watch**
   (รักษาเงินต้นก่อนหาไม้ใหม่ — สำคัญกว่าคะแนน)

4. `halts` ไม่ว่าง → ขึ้นก่อนทุกอย่าง และ **ห้ามเสนอ entry ใด ๆ ในรอบนั้น**

5. `exit` → บอก entry เดิม ราคาออก กำไร/ขาดทุนสุทธิ และเหตุผล (ชน SL หรือตัด EMA20)

6. `entry` → เขียนให้ครบ:
   - checklist 4 ข้อ ผ่านเพราะอะไร (จาก `checklist[].detail`)
   - Entry / Stop / ระยะ SL% / Position size / Risk เป็นจำนวนเงิน
   - `capped_by_leverage` = true → บอกว่าโดนเพดาน x5 แล้ว
   - **สิ่งที่ระบบไม่รู้ — นี่คือคุณค่าหลักของ skill นี้:**
     ถ้าเป็นหุ้น US ให้ค้นเว็บว่ามี earnings ใน 7 วันข้างหน้าไหม
     ถ้าเป็น XAU/crypto ให้ดูว่ามีเหตุการณ์ใหญ่ค้างอยู่หรือเปล่า
   - ถ้าไม่ใช่ BTC → เตือนว่า v5.1 ยังไม่มีหลักฐานฝั่งบวกสำหรับตัวนั้น
     (หุ้น US ทั้ง 13 ตัวยังไม่เคยผ่าน backtest เลย ยกเว้น NVDA)

7. เรนเดอร์เป็น HTML (ใช้โครงจาก `engine/render.py` เป็นแนวทาง หรือเขียนสรุปเป็นข้อความก็ได้
   ถ้าไม่สะดวกสร้างไฟล์) แล้ว `SendUserFile` เข้าแชท

## กฎเหล็ก

- ไม่พูดว่า "ควรซื้อ/ควรขาย" — พูดว่า "เข้าเงื่อนไขครบ 4 ข้อแล้ว ถ้าจะเข้าให้ใช้ระดับนี้"
- ไม่เดาตัวเลขที่ไม่มีใน JSON ถ้าไม่มีให้บอกว่าไม่มี
- `errors` ไม่ว่าง → ต้องบอกว่าตัวไหนดึงข้อมูลไม่ได้ ห้ามเงียบ
- ตอบภาษาไทย ศัพท์เทคนิคเป็นอังกฤษ กะชับ

## หลังผ่านช่วงทดสอบ

เมื่อ Nana มั่นใจว่าระบบทำงานถูกต้องแล้ว (เทียบตัวเลขกับ TradingView ตรงกัน,
เห็น brief มาสม่ำเสมอ) ให้ปรับ ข้อ 2 กลับเป็น **ส่งเฉพาะวันที่มี entry/exit/halt/error จริง**
เพื่อกัน alert fatigue — v5.1 คาด ~0.7-1 เทรด/เดือน วันส่วนใหญ่ควรเงียบ
