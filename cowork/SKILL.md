# Signal Brief (engine v0.7)

แปลงผลสแกนที่คำนวณมาแล้ว → สรุปที่ Nana อ่านแล้วตัดสินใจได้ทันที
**ห้ามคำนวณ indicator เอง** ตัวเลขทุกตัวมาจากไฟล์ JSON เท่านั้น

## ที่มาของไฟล์

repo เป็น public — อ่านตรงได้ผ่าน raw.githubusercontent.com (ไม่ต้อง auth)
ใช้ path แบบ `refs/heads/main` เสมอ ไม่ใช่ `main` เฉย ๆ (CDN cache 5 นาทีทำให้ได้ของเก่า):

```
https://raw.githubusercontent.com/Naxyz23/agent-trade/refs/heads/main/data/signals_crypto.json
https://raw.githubusercontent.com/Naxyz23/agent-trade/refs/heads/main/data/signals_gold.json
https://raw.githubusercontent.com/Naxyz23/agent-trade/refs/heads/main/data/signals_stock.json
```

⚠️ **ห้ามอ่าน `data/signals.json` หรือ `data/state.json`** — เป็นไฟล์ค้างจาก v0.4
ไม่มีอะไรเขียนทับแล้ว (v0.6 สั่งลบทิ้งใน workflow) ถ้ายังเจออยู่แปลว่า workflow ยังไม่เคยรัน

ถ้าดึงไม่ได้ (404 / connection error) → บอก Nana ตรง ๆ อย่าเดาว่ามีสัญญาณอะไร

## เช็คความสดของข้อมูล 2 ชั้น (v0.6 — สำคัญ)

ของเดิมเช็คแค่ `generated_at` ซึ่งบอกแค่ว่า "เครื่องยนต์รันเมื่อไหร่"
ไม่ได้บอกว่า "กราฟที่ใช้ตัดสินใจสดแค่ไหน" — 17 ส.ค. 2026 ระบบรันตรงเวลาแต่ใช้กราฟเก่า 2 วัน

1. `generated_at` เก่ากว่า 30 ชั่วโมง → GitHub Action ล่ม/ยังไม่รัน
2. `data_health.oldest_bar_age_days` และ `data_health.stale_symbols` →
   ถ้า `stale_symbols` ไม่ว่าง ต้องบอก Nana ว่าตัวไหนใช้กราฟเก่าจนไม่ออกสัญญาณให้

## ขั้นตอน

1. ดึงไฟล์ → เช็คความสด 2 ชั้นข้างบน

2. **ช่วงทดสอบ: ส่งสรุปทุกรอบไม่ว่าจะมีสัญญาณหรือไม่** เพื่อให้เห็นว่าระบบทำงานจริง
   ถ้า `signals` ว่าง → บอกสั้น ๆ ว่า "สแกนแล้ว ไม่มีอะไรเข้าเงื่อนไข" พร้อมเวลาที่สแกน
   และภาพรวม 2-4 บรรทัดจาก `snapshot`

3. ลำดับการเล่า: **halts → exit → entry → blocked → watch**
   (รักษาเงินต้นก่อนหาไม้ใหม่)

4. `halts` ไม่ว่าง → ขึ้นก่อนทุกอย่าง และห้ามเสนอ entry ใด ๆ ในรอบนั้น

5. `exit` → บอก entry เดิม ราคาออก กำไร/ขาดทุนสุทธิ และเหตุผล
   `reason` = `stop` (ชน SL) · `stop_gap` (เปิด gap ข้าม SL) ·
   `ema50_cross` (trail ตัด — v0.8 เปลี่ยนจาก `ema20_cross` เดิม)
   ดูเส้นที่ใช้จริงได้จาก `rules_config.trail_ema` ในไฟล์ signals
   ถ้า `reason` เป็น stop แต่ `close` ยังอยู่ฝั่งดีของ `stop` ให้บอกว่า
   **"ไส้เทียนหลุด SL ระหว่างวัน — SL order บนกระดานตัดไปแล้ว"** ไม่ใช่ราคาปิด

6. `entry` → ระบบเปิดไม้ให้แล้วอัตโนมัติ (v0.7) ไม่ต้องยืนยันอะไร
   - `levels.stop_source` บอกที่มาของ SL: `atr2` = ATR14 x 2 (หุ้น US + XAU ตั้งแต่ v0.8)
     · `swing_low10` / `swing_high10` / `ema50` = SL ตามชาร์ต (crypto ยังใช้แบบนี้)
   - checklist 4 ข้อ ผ่านเพราะอะไร (จาก `checklist[].detail`)
   - Entry / Stop / ระยะ SL% / Position size / Risk เป็นจำนวนเงิน
   - `capped_by_leverage` = true → บอกว่าโดนเพดาน x5
   - ราคาที่ระบบบันทึกคือ **ราคาปิดของแท่งที่ให้สัญญาณ** ของจริงจะได้ราคาเปิดแท่งถัดไป
     ถ้าราคาที่ Nana ได้ต่างจากนี้มาก ให้บอกว่า sync ยอดพอร์ตได้ที่ `data/manual.json`
   - **สิ่งที่ระบบไม่รู้ — คุณค่าหลักของ skill นี้:**
     หุ้น US → ค้นเว็บว่ามี earnings ใน 7 วันข้างหน้าไหม
     XAU/crypto → มีเหตุการณ์ใหญ่ค้างอยู่หรือเปล่า
   - ถ้าไม่ใช่ BTC → เตือนว่า v5.1 ยังไม่มีหลักฐานฝั่งบวกสำหรับตัวนั้น
     (หุ้น US ทั้ง 13 ตัวยังไม่เคยผ่าน backtest เลย ยกเว้น NVDA)

7. `blocked` → เข้าเงื่อนไขครบ 4 ข้อแล้ว แต่กฎ risk ห้ามเปิด
   ต้องบอกว่าถูกบล็อกเพราะอะไร (halt / ช่วงพัก / เต็มเพดานไม้) ห้ามเงียบ

8. `portfolio` → รายงานยอดพอร์ต, drawdown%, และสถานะ halted ทุกครั้งที่ drawdown > 5%

9. `errors` ไม่ว่าง → ต้องบอกว่าตัวไหนดึงข้อมูลไม่ได้ หรือตัวไหนโดนข้ามเพราะข้อมูลเก่า

## data/manual.json — ปกติไม่ต้องแตะ เหลือแค่ 2 ช่อง

```json
{"equity": 103.5, "resume": false}
```

- `equity` — sync ยอดพอร์ตจริงจากกระดาน ถ้าตัวเลขที่ระบบคำนวณเริ่มเพี้ยน
- `resume` — ปลดล็อกหลังโดน halt จาก drawdown 15% (v5.1 บอกให้ทบทวนกฎก่อน จึงไม่ปลดเอง)

ถ้าเจอ `suspicious_data: true` ใน `closed[]` แปลว่าเจอราคาที่เพี้ยนจนขาดทุนเกิน 5 เท่าของ SL
ระบบบันทึกผลที่ราคา stop ตามแผนแทนแล้ว แต่ต้องบอก Nana ให้ไปเช็คยอดจริงและ sync `equity`

## กฎเหล็ก

- ไม่พูดว่า "ควรซื้อ/ควรขาย" — พูดว่า "เข้าเงื่อนไขครบ 4 ข้อแล้ว ถ้าจะเข้าให้ใช้ระดับนี้"
- ไม่เดาตัวเลขที่ไม่มีใน JSON ถ้าไม่มีให้บอกว่าไม่มี
- ตอบภาษาไทย ศัพท์เทคนิคเป็นอังกฤษ กะชับ
